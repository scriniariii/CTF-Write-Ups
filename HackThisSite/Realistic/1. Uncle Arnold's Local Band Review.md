Our buddy HeavyMetalRyan is in a rough spot, and we don't leave a friend hanging, so let's see what we can do about his $500 problem

At first glance the page looks completely normal, a list of bands, each with its own voting widget, nothing weir in the layout itself. 


Each band's rating is submitted through a plain `<select>` element

```html
<select name="vote">
	<option value="1">1</option>
	<option value="2">2</option>
	<option value="3">3</option>
	<option value="4">4</option>
	<option value="5">5</option>
</select>
```

The vote value is entirely defined client-side, in the HTML itself, there's nothing here suggesting the server independently validates that a submitted vote actually falls within the 1–5 range it displays

If the client controls the value, the client can set it to anything. Instead of picking "5," the `value` attribute on one of the options was edited directly in the DOM to something far outside the intended scale

```html
<select name="vote">
	<option value="1">1</option>
	<option value="2">2</option>
	<option value="3">3</option>
	<option value="4">4</option>
	<option value="99999999999999999999999999999">5</option>
</select>
```

Submitting that vote for Raging Inferno sends a rating value the server was never expecting to receive

Raging Inferno rockets to the top of the list, mission accomplished for Ryan's bet
